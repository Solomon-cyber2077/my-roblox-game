## Lighting ownership notes
- Confirmed from repository code: AtmosphereController owns client Lighting properties, Atmosphere and ClockTime (101-166, 382-411, 548-595); Sky.compose supplies the lobby look (630-646).
- LobbyService.Init calls LobbyBuilder.build (47-53). LobbyBuilder creates local PointLights (438-481); it does not write Lighting, ClockTime or Atmosphere. Its lamps complement the client lighting.
- Lobby brightness (verified 2026-10-06): brightness, exposure and ambient live in the LOBBY table in Scenery/Sky.luau (Sky.compose); AtmosphereController cannot override them. The floor is mostly lit by LobbyBuilder's fill and pendant PointLights (about 438-482). Changes under 30% to the global values are barely visible; Rojo only updates Studio's edit copy, so restart play to see changes.
- Each bootstrap requires modules, runs every Init, then every Start. Atmosphere Init replaces existing sky/atmosphere/post effects; Start applies the current sky every RenderStepped.
- Client Net waits for replicated Remotes during require; server NetService.Init creates them before LobbyService.Init. There is no cross-client/server guarantee that the hall finishes before client lighting initializes. No task.wait delays the inspected lighting functions; task.delay schedules thunder only.
- Lobby detection is within 420 studs of the lobby origin. The normal hour is Journey.hour(0, StationCount); a developer hour override takes precedence.
- This is certain for the indexed repository, not the unsynced Studio place described in HANDOFF.md. Live appearance and any Studio-only competing scripts remain unverified.
